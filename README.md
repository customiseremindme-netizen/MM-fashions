# M.M Fashions — website

Marketing site and uniform catalogue for **M.M Fashions, Tirupur** — manufacturers of hosiery garments, sportswear, regular and house uniforms.

React 19 · Vite · TypeScript · Tailwind CSS 4 · shadcn/ui (Radix) · Framer Motion · React Router · Lucide. Static site: no backend, no API keys.

The approved copy and UX spec is [`docs/SITE_SPEC.md`](docs/SITE_SPEC.md).

## Commands

```bash
npm install
npm run dev        # development server on http://localhost:5173
npm run build      # type-check, build, and prerender every page into dist/
npm run preview    # serve dist/ like a static host on http://localhost:4173
npm run images     # regenerate WebP derivatives after changing a photo or model image
```

Node 20.19 or newer (Vercel's default Node 22 works).

## Pages

| Route          | Page                                                              |
| -------------- | ----------------------------------------------------------------- |
| `/`            | Home                                                              |
| `/about`       | About                                                             |
| `/collections` | Four collections and all 12 ranges                                |
| `/catalogue`   | Model finder: `?range=<slug>` filter, `?q=<number>` search, shortlist → WhatsApp |
| `/fabrics`     | Fabrics and customisation                                         |
| `/contact`     | Contact cards, enquiry form, map, FAQ                             |
| anything else  | 404 ("This page isn't here")                                      |

## Where things live

```
src/
  config/site.ts        company details: phones, WhatsApp, email, address, map links
  content/*.ts          all page copy (from docs/SITE_SPEC.md) and SEO titles/descriptions
  data/models.json      the catalogue: 12 ranges, 255 models → single source of truth
  data/photo-manifest.json  generated by `npm run images` (sizes of the supplied photos)
  lib/models.ts         helpers over models.json: getModelsByRange, getRangeBySlug,
                        getModelByNumber, getRangeCount, searchModels, …
  lib/whatsapp.ts       shortlist and enquiry message builders
  lib/seo.ts            head tags, LocalBusiness and FAQPage JSON-LD
  components/           layout, sections, catalogue, shadcn/ui primitives
  pages/                one file per route
  entry-server.tsx      build-time renderer used by scripts/prerender.mjs
public/
  photos/               supplied photos and logo.png (unchanged)
  photos/opt/           WebP derivatives (generated)
  models/mm-XXX.jpg     supplied model images (unchanged)
  models/thumbs/        240/480px WebP thumbnails (generated)
  fonts/                Poppins 400–800, self-hosted
```

**Editing copy:** change the text in `src/content/*.ts`. **Changing a phone number, email or address:** `src/config/site.ts`. **Adding or moving a model:** edit `src/data/models.json` and drop the image in `public/models/`, then run `npm run images`.

### Catalogue data

`models.json` holds 255 entries: the 253 numbered models plus the two page-32 shorts variants, `008 (shorts A)` and `008 (shorts B)`, which sit in the Shorts range alongside the Sports-sets model `008`. Counts shown in the catalogue come straight from this file; marketing copy keeps the approved "250+" and the Home stat keeps "253".

The shortlist is stored in `localStorage` (`mm-fashions:shortlist`) and sent as one WhatsApp message grouped by range.

## Images

The supplied files are used as-is. `npm run images` (sharp) writes WebP copies next to them for faster loading — responsive widths of each photo in `public/photos/opt/` and 240/480px thumbnails of each model in `public/models/thumbs/`. Pages serve these through `<picture>` with the original JPG/PNG as fallback, and the catalogue lightbox shows the original model image. `logo.png` is always served exactly as supplied.

## Build output and hosting

`npm run build` writes a fully static site to `dist/`:

- every route is **prerendered** to its own HTML file (`dist/about/index.html`, …, `dist/404.html`) with its own title, description, canonical URL, Open Graph tags and JSON-LD, then hydrated in the browser;
- `sitemap.xml` and `robots.txt`;
- `_headers` (Netlify, Cloudflare Pages) and `.htaccess` (Apache/LiteSpeed shared hosting) for caching and 404 handling.

**Vercel:** `vercel.json` sets everything (Vite framework, `npm ci`, `npm run build`, output directory `dist`, clean URLs, caching headers), so the project's own framework preset and output-directory settings are overridden and nothing needs changing in the dashboard.

Upload `dist/` to any static host. Serve unknown paths with `404.html` (most hosts do this automatically); do not configure an "SPA fallback" that rewrites every path to `index.html` — it still works, but each page then renders in the browser instead of using its prerendered HTML.

The canonical domain is set in `src/config/site.ts` (`https://www.mmfashions.in`).

## Light and dark mode

The sun/moon button in the header switches themes. Until a visitor chooses, the site follows their device setting; a choice is saved in `localStorage` (`mm-fashions:theme`). A tiny inline script in `index.html` applies the theme before the first paint, so there is no flash of the wrong theme.

Colours that change between themes are CSS variables in `src/index.css` (`surface`, `fg`, `accent`, `red-fg`, plus `chalk`, `body`, `muted`, `line` and the ink tones), redefined under `:root[data-theme="dark"]`. Product photos always sit on white, and the logo sits on a white plate in dark mode because the supplied file has black lettering on a transparent background. Both themes pass an automated WCAG AA contrast check.

## Accessibility and motion

One H1 per page, landmarks, alt text on every image (models read "Model 057, Cut & sew polos"), visible focus rings, 44px minimum tap targets, keyboard-operable menu, accordion and lightbox (arrow keys, Escape). With `prefers-reduced-motion`, all animation is switched off and content shows in its final state. The custom cursor only runs on desktop with a mouse.

The hero headline and page-title intros are CSS keyframes, so they start from the prerendered HTML without waiting for JavaScript; scroll reveals, page transitions, the menu, lightbox, count-up and shortlist bar use Framer Motion.
